## Decision

M69 is accepted:

- RTNN is bridgeable to the generic
  `fixed_radius_ranked_summary_3d_prepared_session` runner surface.
- All 14 frozen RTNN all-app rows map to ranked-summary shapes.
- 13 of 14 rows and 6 of 7 shape groups remain below `1.05x`, so the app-win
  gap remains real.
- The existing repeat50 evidence is not hot-query speedup.
- The repeat50 runner-wall signal is phase-split and must remain bounded:
  - total runner-wall delta: `0.866893s`
  - input load/pack share: `0.323`
  - runner-after-pack share: `0.677`
  - hot-query speedup vs legacy: `0.988781x`
- M70 may draft a focused protocol only; M69 authorizes no runbook execution,
  no POD, no all-app, no public claim, and no release action.

## Carry-Forward To M70

M70 must carry all of these constraints:

1. The repeat50 phase attribution is uniform-distribution evidence only.
2. Per-distribution phase bounds are required before any protocol uses clustered
   or shell shapes.
3. `prepared_execution_ranked_summary` currently requires full-batch
   self-queries.
4. The M70 protocol must name exact frozen RTNN shapes and same-contract
   incumbents.
5. The `0.988781x` hot-query boundary must remain visible.
6. Exact aggregate, productized prepared-session runner, graph partner bridge,
   and paper/author diagnostic rows must not be merged into one public claim.

focused protocol draft with no execution.
