# PIP Point-Location Methodology Note

This artifact replaces the earlier `safe100k` wording with a precise label:
`parity_filtered_100k`.

The query stream is not merely random bbox data. It was generated by producing
candidate points, materializing OptiX and Embree rows before timing, and keeping
only candidates with exact `(point_id, face_id, segment_id)` parity. One tie
candidate was rejected before the timed 100,000-point stream was written.

The old `safe100k` name is retired because it was too easy to misread as a
guarantee before backend parity filtering was actually applied.
