# Goal5835 bounded Sui-derived edge-crossing mapping

## Result

Goal5835 is complete at bounded mapping scope:

```text
GOAL5835_COMPLETE_BOUNDED_SUI_DERIVED_EDGE_CROSSING_MAPPING
```

The case-study code now expresses the selected robot-collision core in the
application's own terms:

1. a constant-radius robot sphere moving over one piecewise-linear path segment
   becomes one swept capsule;
2. each capsule becomes one built-in round-linear curve primitive;
3. obstacle triangles are converted to a deterministic shared-edge-deduplicated
   edge set, or already registered obstacle edges are consumed directly;
4. each edge becomes one finite Boolean curve query;
5. RTDL returns sealed `per_edge_hit` bits and the application exposes
   `collision = OR(per_edge_hit)`.

The implementation is in
`case_studies/sui_derived_edge_crossing_core/`. It includes typed application
objects, trajectory-to-capsule mapping, triangle-edge deduplication, exact
identity reconstruction, a public lifecycle adapter, a second stdlib-only
active-set oracle, frozen-fixture adapter, functional receipt builder and a
reader-facing scope statement.

## Why the result is a real application mapping

This is not a renamed low-level fixture. Every curve primitive is mapped back
to `(sphere_id, path_segment_id)`, and every query is mapped back to an
`edge_id` plus source triangle IDs when available. Two triangles sharing one
vertex-identity pair deterministically produce five, not six, registered
edges; inconsistent coordinates for a shared vertex reject.

The `piecewise_linear_or` case maps two swept path segments and three obstacle
edges to bits `[0,1,0]`, then collision `1`. The face-interior boundary maps an
actual three-edge triangle to `[0,0,0]`, making the method limit visible: this
core detects registered edge/capsule crossing, not collision confined to a
triangle face interior.

## Why no duplicate GPU run was needed

Goal5835 adds the paper/application mapping; Goal5834-B3 already measured the
provider path. For all 11 registered executions, the new mapping independently
constructs public `BuiltinCurveStaticInput` and `CurveBooleanSegmentBatch`
objects whose exact public commitments equal the B3 worker commitments. It
then binds those bytes to B3's sealed raw GPU vector and recomputes the expected
bits with a different active-set distance algorithm.

Thus the evidence chain is exact:

```text
Goal5835 application objects
  == public static/query commitments
  == Goal5834-B3 executed worker bytes
  -> sealed true-OptiX per-query bits
  == Goal5835 independent active-set oracle
```

The resulting 11-row mapping receipt regenerated byte-identically twice at
`ae370da1...`. It records 11/11 matching mappings, 33 inherited functional
true-OptiX launches, zero new Goal5835 GPU launches and zero timings. This is a
composition result, not an attempt to count old launches as a new experiment.

## Exact limitations

The status remains:

```text
paper_app_status: NOT_A_PAPER_APP
source_relation: SUI_DERIVED_MAPPING__AUTHOR_DESIGNED_FIXTURES
generalization_exam_count: 0
```

It is not full Sui RT-CCD. Start-inside/initial overlap, near tangency,
near-parallel contact and face-interior-only collision are outside the current
predicate. Exact time of impact and collided primitive identity are not
exposed. The hit fixtures use explicitly registered obstacle edges; only the
face-boundary fixture reconstructs a complete triangle edge set. All fixtures
and code are author produced.

Goal5836 is still required to pin the exact paper/source relation, introduce a
paper-source fixture, compare with author code on the same input, and run the
mapped application end-to-end on modern RTX. Only that goal may reconsider
Paper App status. Performance and external review remain unauthorized.
