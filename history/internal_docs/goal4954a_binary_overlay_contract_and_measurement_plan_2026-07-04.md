## Purpose

Goal4954-A defines the contract and measurement plan for treating overlay as a
binary intermediate operator instead of a paper text-output program.

This is not an implementation goal. It decides what the next measurement and
implementation goals are allowed to build.

## Controlling Invariant

RTDL is a general spatial dataflow system. RayJoin is an application and a
paper-reproduction stress test on top of RTDL.

Therefore:

- RTDL core may define generic columnar carriers and generic spatial/dataflow
  operations.
- RayJoin may adapt CDB/paper state into those carriers.
- RayJoin may own AuthorOfficial comparison and paper text output.
- RTDL core must not contain RayJoin paper text, AuthorOfficial semantics, CDB
  conventions, or Section 5.7 output-chain identity.

If a proposed core feature cannot be explained without naming RayJoin, it is
not RTDL-core work.

## Generic Binary Contracts

The binary operator line uses two related generic row shapes.

### Contract 1: Spatial Event Rows

Spatial event rows represent geometric events generated by one or more spatial
operators.

Required columns:

| Column | Type | Meaning |
|---|---|---|
| `source_side_id` | `uint8` or `int32` | Which logical input side produced this row. |
| `source_group_id` | `int64` | App-provided group/chain/feature id. |
| `source_element_id` | `int64` | App-provided edge/segment/primitive id. |
| `event_order` | `int64` | Stable ordering key within a group. |
| `x` | `float64` or fixed-point integer | Event coordinate x. |
| `y` | `float64` or fixed-point integer | Event coordinate y. |
| `primary_label` | `int64` | Descriptor/face/region label on the primary side. |
| `secondary_label` | `int64` | Descriptor/face/region label on the other side. |
| `keep` | `bool` or mask integer | Whether this row remains active after app predicate/filtering. |

Genericity rule:

- The contract may say `label`, `group`, `element`, `side`, and `event`.
- The contract must not say `RayJoin`, `AuthorOfficial`, `output_chain`,
  `CDB`, `map0`, `map1`, `polyover`, or `Section 5.7`.

RayJoin app adaptation:

- RayJoin may map polygon side 0/1 to `source_side_id`.
- RayJoin may map polygon chain ids to `source_group_id`.
- RayJoin may map edge ids to `source_element_id`.
- RayJoin may map face ids to `primary_label`/`secondary_label`.

### Contract 2: Grouped Binary Output Rows

Grouped output rows represent the binary intermediate result consumed by a
downstream operator.

Required columns:

| Column | Type | Meaning |
|---|---|---|
| `group_id` | `int64` | Generic group id. |
| `item_order` | `int64` | Order of item within group. |
| `x` | `float64` or fixed-point integer | Coordinate x. |
| `y` | `float64` or fixed-point integer | Coordinate y. |
| `label_a` | `int64` | First descriptor label. |
| `label_b` | `int64` | Second descriptor label. |
| `source_side_id` | `uint8` or `int32` | Source side, if relevant. |
| `source_element_id` | `int64` | Source primitive id, if relevant. |
| `group_offset` | `int64` | Optional offset for columnar grouped representation. |
| `group_length` | `int64` | Optional length for columnar grouped representation. |

This is intentionally not a text format. It is an intermediate columnar result.

## Measurement Workload

The measurement workload is the public RayJoin Section 5.7 sample already used
as the correctness anchor.

The paper-output line remains responsible for byte-for-byte correctness. The
binary-operator line measures performance after removing the paper text writer.

The same input must be used for all measurements within Goal4954-B:

- same CDB/input pair;
- same AuthorOfficial comparator version;
- same repaired RTDL correctness path;
- same machine and build;
- warm/prepared runs clearly separated from cold/setup runs.

## Author Comparator

Goal4954-B must compare two different things separately:

1. Paper-output correctness:
   - RTDL paper output vs AuthorOfficial/public answer.
   - This remains a byte-equality or hash correctness anchor.

2. Binary operator performance:
   - RTDL writer-free binary operator phases vs AuthorOfficial overlay-compute
     reference.
   - Do not compare writer-free RTDL against author text dump.

If the exact AuthorOfficial overlay-compute phase cannot be isolated in a run,
Goal4954-B must mark the comparator as `author_overlay_compute_reference_missing`
and must not claim competitiveness.

## Downstream Consumer Choice

Goal4954-A selects the first downstream consumer:

`descriptor_pair_count`

Definition:

- input: grouped binary rows;
- consume `label_a` and `label_b` columns;
- compute counts per `(label_a, label_b)` pair;
- output a small aggregate table.

Why this consumer:

- It is generic spatial/dataflow work.
- It does not parse paper text.
- It does not require paper output-chain semantics.
- It proves the binary overlay result can feed a downstream operator.
- It can be reused by a non-RayJoin spatial overlap/counting workload.

RayJoin-specific interpretation of labels remains in the app layer.

## Non-RayJoin Proof Requirement

Before any new carrier or consumer is promoted as RTDL core progress, Goal4954
must include a non-RayJoin proof.

Minimum acceptable proof:

- construct or reuse a small non-RayJoin spatial pair/intersection dataset;
- produce generic event/grouped rows with the same carrier;
- run `descriptor_pair_count` or an equivalent generic consumer;
- show no RayJoin imports, no CDB dependency, no AuthorOfficial dependency, and
  no paper-output text dependency.

If this proof is not available, the work may continue as RayJoin app work but
cannot be counted as RTDL core progress.

## Decision Gates

### Gate 1: Contract Validity

Pass if:

- schema names are generic;
- RayJoin mapping is explicitly app-owned;
- no paper text or AuthorOfficial semantics are in the generic contract.

Fail if:

- the schema cannot be understood outside RayJoin;
- the schema uses paper-output identity as a core field.

### Gate 2: Measurement Validity

Pass if:

- writer-free binary route excludes paper text formatting;
- paper text writer is still measured only as correctness sink;
- author comparator is overlay compute, not text dump;
- phase table separates cold/setup from prepared-hot operator time.

Fail if:

- the measurement hides writer or setup costs;
- it compares different workloads or different inputs;
- it presents writer removal as closing the compute gap.

### Gate 3: Generic Progress Validity

Pass if:

- a non-RayJoin consumer/test uses the same generic carrier or operation.

Fail if:

- the only consumer is RayJoin;
- the only correctness evidence is AuthorOfficial byte equality.
