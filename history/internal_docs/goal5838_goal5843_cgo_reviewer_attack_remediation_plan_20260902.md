# Goals 5838--5843: CGO reviewer-attack remediation plan

Date: 2026-09-02

Status: `OWNER_REQUESTED_PLAN__NO_EMPIRICAL_CLAIM_ADDED`

This plan follows Goal5837. It does not reclassify the owner-grouped successor,
change either stable V4 constructor, add a prospective success, or authorize a
performance, usability, field-defect, Paper-App, or generality claim by itself.
Each goal below must preserve negative outcomes rather than repairing an exam
after observing its result.

## 2. Goal5838: generic core freeze and prospective new-topology exam

Purpose: answer R1 without retrospectively promoting Goal5837 or selecting an
easy challenge because it fits current code.

### Stage A -- preregister the experiment before generic-core work

1. Freeze the exact current source, two stable constructors, one root-exported
   successor, and zero prospective successes.
2. Freeze structural success criteria and forbidden core locations.
3. Freeze a challenge-selection procedure, but do not reveal/select the actual
   challenge until Stage C seals the generic core. Prefer an external reviewer
   draw from a complete, pre-enumerated topology table. If external selection
   is unavailable, wait; do not substitute an author-chosen convenient case.
4. Declare in advance that any post-selection change to frozen generic-core
   bytes makes the prospective attempt a scientific `FAIL`.

### Stage B -- implement and freeze the generic core

1. Complete the currently noncontrolling `src/rtdsl/v4_family_schema.py`
   direction as a provider-independent schema admission and canonical
   compilation plan.
2. Migrate the two stable constructors and the owner-grouped successor through
   declarative shapes without changing their public classifications.
3. Remove concrete application names and concrete-family dispatch from the
   generic admission/compiler/lifecycle core. Provider modules may retain
   platform-specific geometry and trusted lowering.
4. Demonstrate package-external provider conformance. This tests extensibility
   but does not count as the prospective application/topology result.
5. Preserve exact functional behavior, fail-closed status, executable identity,
   and current public lifecycle tests.
6. Seal the generic-core file set and publish an exact verifier before challenge
   selection.

### Stage C -- run the prospective attempt

1. Obtain and record the independently selected new topology.
2. Express it only through the frozen schema, verified Callback IR, provider
   plugin surface, and app-owned code.
3. No edit to the sealed generic core is permitted. A needed edit records
   `PROSPECTIVE_EXAM_FAIL__CORE_INCOMPLETE`; a later repaired system requires a
   fresh challenge and cannot recover this attempt.
4. Require an independent CPU oracle, hostile cases, public lifecycle execution,
   and true-GPU evidence on the exact sealed deployment before a success count.

Pass condition: one preregistered new topology reaches the public GPU lifecycle
with zero sealed-core byte changes and exact oracle agreement. A failed exam is
still a valid and mandatory scientific result.

## 3. Goal5839: real-artifact protocol-property census

Purpose: answer R2 by measuring whether the problem exists outside constructed
faults.

1. Freeze inclusion/exclusion rules before inspecting candidate source. The
   preferred denominator is every public OptiX RT-repurposing artifact in a
   pinned survey/cutoff that is buildable or statically inspectable at an exact
   public revision.
2. Freeze the five protocol properties and the only allowed labels:
   `ENFORCED`, `UNCHECKED_BUT_APPARENTLY_CONSISTENT`, `VIOLATED`, and
   `UNRESOLVED_WITH_REASON`.
3. Preserve repositories, revisions, licenses, source inventories, callback
   roles, payload/attribute meanings, physical bindings, status/continuation,
   and executable construction evidence.
4. Require two independent protocol extractions or one extraction plus external
   adjudication before a paper claim. The project author alone cannot resolve an
   ambiguous row in the favorable direction.
5. Notify upstream authors and offer a patch before naming a concrete violation.
6. Report the complete denominator, including zero-violation and unresolved
   outcomes. Do not convert absence of an explicit check into a confirmed bug.

Pass condition: a paper-auditable complete-denominator table. The scientifically
valid outcome may be zero violations; the goal measures prevalence rather than
requiring a favorable result.

## 4. Goal5840: independent lowering/refinement evidence

Purpose: answer R3 while preserving the current bounded claim.

1. Specify the supported Callback-IR subset and observable protocol behavior.
2. Implement a target-side extractor/checker that does not import declaration-
   side projection builders and derives facts from generated provider artifacts,
   ABI metadata, and runtime receipts.
3. Establish a bounded preservation argument for types, role effects, nominal
   channels, status-before-output, and executable identity across source, IR,
   compiled ABI, provider artifact, and execution receipt.
4. Mutate generated source/IR/PTX metadata, SBT/buffer bindings, status paths,
   and executable identities after declaration admission; require independent
   target-side rejection or a registered residual classification.
5. State the TCB and unproved obligations explicitly. Do not call executable
   tests a general soundness theorem.

Pass condition: every claimed supported lowering rule is covered by the bounded
preservation argument and independent mutation suite; uncovered rules are
removed from the theorem statement or the claim fails closed.

## 5. Goal5841: external-human authoring case series

Purpose: answer R4. Begin recruitment/administrative work in parallel, but do
not run the study until Goal5838 freezes the public authoring interface.

1. Obtain an institutional/ethics determination before collecting participant
   observations.
2. Recruit at least two developers outside the project. AI agents, project
   collaborators who built the system, and author-guided sessions do not count.
3. Give each participant a preregistered task and only the public package/docs.
4. Record completion, time, documentation failures, requested assistance,
   private-API attempts, invalid protocols rejected, and any task not completed.
5. Compare against a clearly defined alternative authoring route only if the
   study design and participant burden are approved in advance.

Pass condition: at least two valid external-human observations with the full
denominator reported. This may establish bounded learnability evidence, not
universal ease or productivity superiority.

## 6. Goal5842: causal admission-cost and fair-baseline evaluation

Purpose: answer R5 after Goals5838 and 5840 stabilize the measured system.

1. Preregister tasks, hardware, phase boundaries, warmup, repetitions, ABBA
   ordering, statistic, confidence procedure, and failure handling.
2. Add checker-on and checker-off arms that consume byte-identical generated and
   native artifacts; only admission work may differ.
3. Report validation, materialization, native prepare, first execution, steady
   execution, and close separately in absolute time.
4. Retain strongest-native payload semantics; add an OWL timing arm where the
   same task/physical algorithm can be matched; explain Direct phase composition.
5. Use at least two GPU generations and at least three matched tasks if exact
   same-contract routes exist. Fail closed rather than manufacture a comparator.
6. Apply no RTDL-only optimization and define no new timing regime after seeing
   results.

Pass condition: the causal cost of admission can be separated from provider
setup, and every public performance sentence identifies task, route, artifact,
target, statistic, and adverse rows.

## 7. Goal5843: manuscript reconstruction and final claim gate

Purpose: integrate only evidence that survived Goals5838--5842.

1. Rewrite the contribution and limitations around actual outcomes, including
   failed or zero-result goals.
2. Keep protocol admission distinct from automatic RT mapping and application
   correctness.
3. Rebuild the complete claim-source matrix and compact reproducibility capsule.
4. Perform separate manuscript and artifact double-blind scans.
5. Obtain external critical review when the owner's temporary travel constraint
   ends. Internal self-review is not multi-AI or independent consensus.
6. Freeze exact source/PDF/artifact bytes only after all scientific edits.

Pass condition: every quantitative and qualitative claim has an exact source,
all negative results are adjacent to positive ones, no superseded result is
resurrected, and the final anonymous artifact verifies from a clean extraction.

## 8. Execution order and immediate decision

Critical path:

```text
Goal5838 A/B core freeze
    -> Goal5838 C prospective exam
    -> Goal5840 independent refinement evidence
    -> Goal5842 causal cost/performance
    -> Goal5843 manuscript/final gate
```

Parallel paths:

```text
Goal5839 field census -----------------------> Goal5843
Goal5841 recruitment/admin -> authoring study -> Goal5843
```

The immediate engineering goal is Goal5838 Stage A/B. Goal5839's protocol may
be preregistered in parallel, but source inspection must wait until that freeze.
Goal5841 administrative work may begin, but observations wait for the frozen
interface. Goal5842 must not benchmark a moving generic core.

Additional benchmark ports, application renaming, performance tuning, audit
volume, and retrospective promotion of Goal5837 do not answer the primary
reviewer attacks and are not substitutes for this sequence.

## 9. Deadline reality

This programme cannot honestly turn zero prospective exams and zero external
authors into mature evidence within a few days. For a near-term submission, the
current bounded paper may still be submitted with those zeros explicit. The
plan above is the path to a materially stronger follow-on paper; compressing it
by weakening preregistration, selecting an easy challenge, using an AI as an
external user, or hiding negative outcomes would invalidate the evidence rather
than accelerate it.
