# Strict self-review — Goals 5831 and 5832

## Verdict

**P0=0, P1=0 within the declared Goal5831/5832 scope; P2=6, P3=2.** Both
goals are complete only at terminology/denominator and protocol-shape
specification scope. They are not a generalization result and must not be used
as one. No external review was requested.

## Hostile questions and answers

### Did we turn an implementation enum into the scientific universe?

No. The result publishes all relevant denominators separately: 6 platform
build inputs, 4 leaf primitives, 2 implemented physical kinds, 2 fixed
constructors, 1 bounded authoring template, 9/13 author-built systems/lanes,
and an open application-semantic universe. The last one has no finite coverage
percentage.

### Did we hide an existing public GPU extension point?

No. The earlier manuscript did, incorrectly. The current paper and public docs
now disclose the caller-authored built-in-triangle `u32x3` template and its
fixed physical/ABI limits. Particle is also disclosed as its public
specialization.

### Did we invent a universal law from two chosen examples?

No. The two physical kinds were author-selected for platform-produced versus
callback-produced hit boundaries and application fit. The report explicitly
denies prospective selection, representativeness, and open-universe coverage.

### Is Goal5832 a generic family compiler?

No. It is a specification, canonical identity implementation, repository-scope
validator, and adversarial KAT suite. The actual compiler/provider still has
concrete-family branches. Any paper sentence that upgrades Goal5832 to
“family-parametric GPU compilation” is false.

### Could the validator pass while a new family remains impossible?

Yes—and that is the largest remaining scientific gap. The validator checks the
authority and identity algebra; it neither lowers arbitrary shapes nor creates
new OptiX build graphs. Generalization exam count correctly remains zero.

## Remaining P2 limitations

1. **No generic compiler.** New geometry or topology still requires
   implementation-core work; Goal5833/5834 must remove concrete-family
   dispatch before any prospective exam.
2. **Manual support-stage classification.** Counts and source enums are
   mechanically checked, but some vocabulary/verifier/provider/public/GPU
   stage labels are curated rather than derived from complete executable
   migration descriptors.
3. **Author-selected cases.** Triangle and custom primitive were not selected
   prospectively or randomly and cannot establish representativeness.
4. **Bounded authoring evidence only.** The public source template is fixed to
   triangle `u32x3`, trace depth one, callable depth zero, and project-authored
   uses; it is not arbitrary Callback IR or third-party usability evidence.
5. **Open universe.** Application-semantic protocols have no finite total;
   therefore no “percentage of all protocols” can be reported.
6. **Submission artifact unfinished.** The content-first paper is 17 pages and
   has not undergone final page-limit compression or the final independent
   double-blind scan.

## P3 observations

1. Git object resolution remains broken (`git status` reports `bad object
   HEAD`). This does not invalidate file hashes or tests, but no commit claim
   is permitted until repository metadata is repaired separately.
2. Goal5832's 23 unit tests are focused hostile KATs rather than a
   property/fuzz campaign.
   Broader generative testing is valuable only after a generic compiler exists.

## P1 defects found and closed during this self-review

The first validator could still PASS after changing the authority to claim a
family-parametric GPU compiler and promoting curves to full support. It also
gave identities to schema-only and unknown-field documents. Both were P1:
green output overstated what the checker established.

The successor now exact-checks scope, implementation status, public surface,
selection rationale, identity membership, canonicalization, typed-schema
status, equivalence, the complete support matrix, scientific outcomes and the
complete claim ceiling. Scientific identities now pass recursive exact typed
validators for family shape, protocol instance and deployment. Dedicated
hostile tests require overclaim, support promotion, empty/garbage documents,
bool-as-int, illegal effects, broken operators/continuations, bad typed
bindings and incomplete deployments to fail. This repair adds no compiler or
GPU capability and does not increase generalization count.

## Kill criteria for the next stage

- Adding a third enum branch or copied wrapper is implementation coverage, not
  family-parametric progress.
- If a frozen-core new-geometry exam requires a generic-core change, that exam
  is a scientific failure even if a later repair makes it run.
- A new application inside an existing shape is reuse evidence, not a new
  family exam.
- CPU-only acceptance or a synthetic provider proves an extension interface,
  not GPU generalization.
- No claim may rise above “identity/specification complete” until the generic
  compiler exists and survives a prospective zero-core-diff challenge.

## Self-review conclusion

These goals resolve the conceptual error that previously made any generality
claim unmeasurable: the project now knows precisely what “same family” means
and what the finite platform denominators are. They do **not** close the CGO
generality gap. Their value is that the next experiment can now fail honestly;
it can no longer be rescued by renaming a case, changing the denominator, or
calling another hard-coded branch a family-parametric compiler.
