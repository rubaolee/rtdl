## Research question

The CGO R3 attack is valid against the current implementation: declaration-side
facts and `compiler_projection` are produced in the same lifecycle module, and
the existing detached verifier checks the stored projection's custody rather
than independently recovering its semantics from generated target artifacts.

Goal5840 asks whether a separate checker can recover the five claimed protocol
properties from exact wrapper/leaf source, ABI, PTX, physical bindings, native
descriptor and runtime receipt, without importing RTDL's declaration-side or
compiler projection builders.

## Frozen scope

The test covers exactly three existing positive routes:

1. Stable bounded relation with fail-closed canonical bounded pair collection.
2. Stable built-in-triangle checked `u64` reduction, including all-hit and
   weighted-hit modes.
3. Goal5838's bounded prospective built-in-sphere any-hit count-and-continue
   topology.

It excludes arbitrary Callback IR, the owner-grouped successor, every unselected
Goal5838 topology, non-OptiX providers, applications, performance and a general
compiler soundness theorem.

## Independent evidence rule

The target evidence bundle must retain the exact public declaration, verified
IR, compiled ABI, generated leaf and wrapper sources, leaf/wrapper/composed PTX,
family schema and plan, provider/native descriptor, SBT and buffer binding,
target/DSO identity, status/completeness record and execution receipt.

The standalone extractor is Python-stdlib-only. It may not import `rtdsl`, any
declaration projector or the existing compiler projector, and it may not read a
stored `compiler_projection` as target fact. Unknown syntax or absent evidence
fails closed as an unsupported rule. Every recovered fact must cite its exact
evidence object, path and symbol. When a fact has an executable representation,
it must be anchored in raw generated source or PTX as well as structural
ABI/plan/binding/receipt evidence. A nominal-only fact must cite independently
identified producer and consumer structural origins.

## Prospective mutation matrix

Each of the three routes receives one predeclared mutation for each of CP001 to
CP005, for 15 route/property units. Mutations occur after declaration admission
and recompute every attacker-controlled bundle-local digest so that a trivial
hash mismatch is not the only defense:

- CP001 changes a generated effect or required role symbol.
- CP002 swaps a same-width nominal semantic or ownership edge.
- CP003 changes geometry/template, SBT, buffer, reducer or native binding.
- CP004 removes/reorders status-before-output or marks incomplete output valid.
- CP005 swaps generated source/PTX, native DSO, target or receipt identity.

The machine authority additionally freezes the exact logical target selector
and replacement for every one of the 15 units; implementation may not choose a
different, easier mutation after observing the extractor.

Every mutation must be rejected before GPU launch. If the extractor cannot
cover a lowering rule, that rule must be removed from the bounded preservation
statement or Goal5840 fails closed.

## Pass and claim boundary

A pass requires exact positive bundles for all three routes and modes, 15/15
mutation rejections, one true-OptiX positive receipt per route, zero changes to
the Goal5838 frozen core, and an explicit TCB/unproved-obligation report.

This preregistration establishes none of those results. It authorizes no
lowering-preservation claim, GPU result, performance result, soundness theorem,
CGO wording, external review or consensus.
