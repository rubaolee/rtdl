# Goal5848 local hostile self-review

Date: 2026-09-05

Verdict:
`ACCEPT_LOCAL_IMPLEMENTATION_FOR_GPU_FREEZE__FORMAL_EVIDENCE_0_OF_2`

This is an internal implementation review, not an external review, GPU result,
performance result or manuscript authorization. Goal5848 remains active until
both distinct RTX generations pass every frozen gate.

## 1. What was reviewed

The review covers the Goal5848 packed workloads, five comparison arms, exact
AOT cache, provider-overlap change, device artifact builder, preflights,
formal controller, independent authorities, tests and one-shot pod runbook. It
also reviews the production changes in `v4_rtdlexe.py` and the OptiX native
context code for benchmark leakage and safety regression.

## 2. Findings fixed before freeze

### F1. Benchmark cache policy leaked into the production engine

Severity: P1. Status: fixed.

The first implementation unconditionally called
`optixDeviceContextSetCacheEnabled(created, 0)` in the native singleton. That
would have traded production startup performance for Goal5848 repeatability
and embedded experiment policy in the engine. The fix introduces the generic
`RTDL_OPTIX_DISK_CACHE_POLICY` setting. The default and explicit `enabled`
state preserve OptiX's normal cache; exact `disabled` turns it off; any other
value fails closed. The Goal5848 runbook sets `disabled`, and idiomatic
PyOptix, strong PyOptix and Direct OptiX also disable their context caches.

The exact Goal5847 predecessor does not contain this new setting. This does
not enter AC5 because AC5 compares prepared steady execution only, after
module admission. Predecessor startup values must not be used as a cache-fair
post-import comparison.

### F2. Shared PTX/CUBIN provenance was too weak

Severity: P1. Status: fixed.

The shared products are now generated by two fresh, untimed NVRTC child
processes and accompanied by a strict receipt. Validation binds tracked source
bytes, source commit/tree/clean status, Python launcher bytes and invocation
path, child argv/cwd/PID relationship, exact compile options and target,
OptiX header repository and API version, product bytes, and the loaded NVRTC
and NVRTC-builtins regular-file identities. No formal worker or registered
performance timer is present in this build step.

The receipt deliberately states
`SOURCE_AND_PRODUCT_BOUND__NOT_A_HERMETIC_CUDA_HEADER_CLOSURE`. This is not a
claim that every transitive CUDA header is archived. The native build manifest
does inventory the host header trees; the standalone device receipt binds the
source, compiler images and products. This limitation must remain visible.

### F3. AOT cache-hit authority was hash-bound but not semantically recounted

Severity: P1. Status: fixed.

The AOT qualification now requires exactly ten fresh processes: five per task.
The standard-library authority independently checks the worker set, distinct
PIDs, candidate binding, zero producer calls, zero compiler modules, zero
NVRTC mappings, exact verification capability, no retries/discards, and both
the `<=1 s` and `<=0.10x cold` gates. These qualification timings are not part
of the 80-cell formal estimators.

### F4. A single authority file was insufficient custody evidence

Severity: P1. Status: fixed.

The pod runbook now executes the independent single-generation authority
builder twice against the same immutable transaction and requires the two
outputs to be byte-identical. Both files are included in the evidence manifest
and archive. The cross-generation builder refuses a generation lacking its
byte-identical `.recount.json` companion.

### F5. Output inside the source checkout could invalidate a late stage

Severity: P2. Status: fixed.

The runbook canonicalizes the output parent and rejects any output root inside
the Git checkout before creating evidence. This prevents the run itself from
silently making the source dirty.

### F6. Failure-path resource ownership was incomplete

Severity: P1. Status: fixed.

The RTDL worker could leave an initializing provider alive when artifact load
or typed-input construction failed, and the strong-PyOptix adapter could skip
close when load or prepare failed. Admission now closes every acquired layer
on all of those paths. Cleanup failures are retained without replacing the
original failure. Three focused fault-injection tests cover artifact load,
typed-input construction and strong-adapter load/prepare failures. The
timer-free RTDL preflight now reuses the same admission/cleanup ownership and a
fourth test proves that its typed-input failure closes the initializing
provider. A fifth fault injection makes both parallel provider-admission
branches fail, verifies that the primary exception is preserved, retains the
secondary failure as a note, and leaves no native-image lease.

### F7. The independent transaction authority trusted an incomplete freeze

Severity: P1. Status: fixed.

The first authority builder checked only a subset of preregistration fields and
required a process command merely to be a list. It now independently
reconstructs the complete frozen preregistration, every one of the 80 exact
worker commands, worker Python version and source tree, and current,
predecessor and PyOptix Git identities. A separate cross-implementation test
compares controller and authority command reconstruction for all 80 schedule
cells. Coherently resealed threshold, command, worker-runtime and Git-binding
changes fail closed.

### F8. Formal process placement and environment were not evidence-bound

Severity: P1. Status: fixed.

The command alone did not prove its working directory, module search path,
visible device, cache policy or user-site isolation. Every formal process row
now records an exact execution context. The independent authority reconstructs
that context from frozen source identity and fixed formal policy. The
controller rejects a mismatch in `CUDA_VISIBLE_DEVICES`, both cache controls,
`PYTHONDONTWRITEBYTECODE` or `PYTHONNOUSERSITE` before worker zero. It also
requires the runbook's CUDA synchronization/JIT/injection, CuPy/Numba cache,
Python injection and BLAS-thread environment variables to be absent. Every
process receipt records those absences and the independent authority
reconstructs them. A coherently resealed context substitution is rejected, and
a runbook-to-controller test prevents the shell sanitization list from
silently falling behind the formal gate.

### F9. Optimized Python and ambiguous JSON could weaken fail-closed recount

Severity: P1. Status: fixed.

Formal validators contained type-narrowing `assert` statements that disappear
under `python -O`, and default JSON parsing accepted duplicate keys and
non-finite constants. Formal Goal5848 production paths no longer use asserts.
Every Goal5848 JSON ingress now uses strict decoding that rejects duplicate
keys and `NaN`/infinity before contract validation; the reusable production AOT
cache owns the same rule without importing experiment code. The full focused
suite passes in ordinary and optimized Python modes, and raw duplicate-key/non-
finite authority and cache-manifest inputs are rejected.

### F10. Exact-AOT publication could expose a partially hardened entry

Severity: P1. Status: fixed.

The first cache implementation renamed a complete entry into the public cache
namespace before tightening its directory permissions. A failed post-rename
hardening step could therefore leave a cache-hit-visible entry after the
producer returned failure. Publication now hardens payload containment before
rename and rolls the entry atomically back into staging if root hardening
fails. Fault injection covers failures both before and after rename and proves
that no public entry remains. A separate exhaustive request test proves that
each of the thirteen bound source, route, task, target, toolchain, build,
compiler and signing fields changes the exact cache identity.

### F11. Phase instrumentation was asymmetric across measured Python arms

Severity: P1. Status: fixed.

The reviewed worker made RTDL endpoint subphase probes conditional on the
explicit `phase_instrumentation` flag, but idiomatic and strong PyOptix called
the same probes unconditionally. Even if the probe cost were small, this was an
unjustified measurement asymmetry and contradicted the stated opt-in policy.
All three Python arms now use the same flag and the same conditional measuring
helper. Formal RTDL, idiomatic-PyOptix and strong-PyOptix receipts must record
`phase_instrumentation: true`; validators reject a coherently resealed receipt
that omits it. Ordinary execution keeps probes disabled. A hostile contract
test covers both PyOptix arms, and the failure-cleanup fixture carries the same
explicit policy.

### F12. A cross-goal runtime-session test never built a valid target manifest

Severity: P2. Status: fixed test fixture; production behavior unchanged.

The Goal5809 nested-artifact admission test wrote arbitrary text into its
`runtime_manifest` and `target_observation` paths even though the current
Goal5805 validator requires complete sealed JSON objects. The test therefore
failed before reaching the nested candidate mutation it claimed to test. The
same failure reproduces at the pre-Goal5848 `HEAD`, so it is not a Goal5848
regression. The fixture now builds the exact observation/runtime schemas,
rehash-bound measurement and runtime file records, and valid seals. Its four
tests pass and the intended mutated triangle-artifact rejection is exercised.

## 3. Architecture and safety review

The two frozen tasks exercise distinct app-independent protocol families:
bounded custom-AABB relation and checked built-in-triangle reduction. No
RayDB, graph, collision, force law or paper-specific predicate was added to the
engine. Packed host adapters express generic typed columns only.

Provider initialization overlaps CUDA primary-context readiness with opening,
reading, hashing and loading the exact sealed native image. Neither side may
publish a provider. `bind` joins them and rechecks deployment, authority,
artifact, family, executable, native and compute-capability identity. Failure
on either side releases both resources. Timing collection is exact-bool,
explicitly opt-in, and empty on the ordinary path.

The AOT cache is content addressed by source, family, route, task semantics,
native target, toolchain, build roots, compiler sources and signing policy.
Every hit rehashes all payloads and reruns deployment/artifact verification.
The hit path cannot invoke its miss-only producer. Corruption, symlinks,
request drift, concurrent publication, incomplete hardening, missing outputs,
duplicate manifest keys and non-finite manifest values are covered by
fail-closed tests.

The formal controller launches one fresh process per scheduled cell, retains
all samples, writes process stdout/stderr evidence, terminates on first
failure, and never retries or pools a prior attempt. Ratios use integer
within-block estimators. Relation and triangle pass independently; no pooled
task result can hide failure. The independent authority imports neither the
controller nor RTDL/GPU packages, reconstructs commands and execution context,
strictly decodes every authority input, and verifies all three Git trees.

## 4. Remaining risks and limits

No unresolved local P0/P1 issue is known inside the bounded design. The
following evidence gaps remain and are blocking for completion:

- GPU evidence is `0/2` architecture generations.
- Native CUDA/OptiX compilation has not been exercised after the final local
  edits because this macOS host has no NVIDIA toolchain/device.
- Strong PyOptix competence, post-import parity, Direct proximity,
  successor/predecessor regression and AOT timing gates have no Goal5848 GPU
  values yet.
- The evidence archive stores original absolute paths inside signed/hash-bound
  receipts. Same-host recount is performed twice before packaging; arbitrary
  cross-host extraction does not by itself rebase those paths.
- CUDA-header closure for the standalone PTX/CUBIN derivation is explicitly
  non-hermetic, as described in F2.
- Test signing roots demonstrate protocol mechanics only; no production key
  custody is claimed.
- ShellCheck is unavailable on this Mac. Bash syntax and a structural runbook
  test pass, but actual Linux execution is still required.
- External review is intentionally deferred and manuscript claims remain
  unauthorized.

Any first-generation failure is retained as adverse evidence. Repair requires
a new committed source identity and complete new transaction; no failed row
may be discarded or pooled.
